# GA4／GSC 趨勢判讀規則

給 `daily-morning-brief`、`imagemarker-seo-monitor` 等排程任務使用。
兩個任務目前都以 **7 天** 為比較基準，容易被峰值週誤導。

## 規則：7 天有異常時，補看 28 天

> GA4 的 7 天比較容易受峰值週影響。如果 7 天趨勢顯示下降，額外查看 28 天趨勢
> 確認是真正下降還是正常回歸。

判讀方式：

| 7 天 | 28 天 | 結論 |
| --- | --- | --- |
| 下降 | 下降 | 真的在跌，值得深入查原因 |
| 下降 | 持平或上升 | 上一週是峰值，這是回歸基準線——不要當成問題回報 |
| 上升 | 持平 | 單週波動，不要當成成長回報 |

**不要改成只看 28 天**：28 天會把剛發生的問題稀釋掉，日報需要 7 天的靈敏度。
7 天負責偵測、28 天負責確認。

## 兩個常見的假訊號（本站已踩過）

1. **埋點上線日不同**：比較兩個事件的曝光／點擊比率之前，先用 `git log -S "<事件名>"`
   查各自的上線日。日期不同就不能直接比。詳見 CTA 漏斗那次的誤判。
2. **內部蠶食**：某頁「排名改善但曝光腰斬」時，先查同期是否有新文章上線搶同一組
   query，而不是先假設被降權。

## 回報時的措辭

7 天下降但 28 天沒下降時，明確寫成「單週回歸，非趨勢性下降」，
不要只寫「流量下降 X%」——那會讓人誤判要動手修。
